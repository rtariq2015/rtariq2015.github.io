Raspi Cloud Sync Pro

Privacy policy

Effective date: November 14, 2026

About the application

Raspi Cloud Sync Pro is open-source software operated on a Raspberry Pi controlled by its owner or organization. The project is maintained by GitHub user rtariq2015. Its Google Drive backup functions run on that device and communicate with Google. The reviewed design does not provide a separate project-operated cloud storage service.

Google permissions

The application requests https://www.googleapis.com/auth/drive.file.

This permission limits access to files and folders created by, opened with, or otherwise authorized for the application. It does not grant unrestricted access to every file in your Drive. It permits file management, including changes and deletion, within that authorized access; it is not a read-only permission. The current backup workflow uses it to upload versioned backups and read their contents for verification, without automatic deletion. See Google’s scope description.

Google handles account sign-in. The application receives OAuth authorization tokens rather than your Google password. Offline authorization allows the backup worker to obtain access while you are not actively signing in.

Files and Google data processed

Eligible files captured from CLOUDSTICK are copied into private local staging. Their contents and relative filenames are uploaded to the configured Google Drive destination. The application accesses the Drive file and folder information needed to locate, upload and verify those backups. Version 1 does not establish a QA-folder-only inclusion filter; files placed on the USB volume may be included.

Verification reads cloud file contents and compares their SHA-256 hashes with the captured local versions. A successful upload alone is not recorded as a verified backup. Historical verification does not continuously detect later changes or deletion in Google Drive.

Local storage and records

The device retains original files, staged contents and manifests. Metadata includes filenames or relative paths, file sizes, hashes, destinations, job status, attempt counts, retry times, timestamps and error codes. USB ownership and recovery records support safe capture. Operational reports and system logs may retain service and diagnostic information. Incomplete staging work may also remain for review.

The backup adapter suppresses raw rclone output and records controlled error codes. This does not establish that every operating-system, hosting-provider or manually collected diagnostic log is free of personal information.

Credentials and access protection

OAuth access tokens, refresh tokens, client configuration and related preparation records are stored locally. The implementation restricts sensitive files to their service identity using private directories and file permissions, including mode 0600 credential files. Separate prepared, operational and administrator-created backup copies may remain.

These controls are not encryption at rest. Device administrators, compromised privileged software or someone able to read an unencrypted card may access stored data and credentials. The ordinary USB storage volume is also accessible to its attached computer; private staging permissions do not encrypt or authenticate that USB volume.

Data transfers and access by others

Google receives the backup contents and associated metadata. Google’s policies and your Drive sharing settings govern access on its service. The application does not add public sharing as part of the core backup workflow.

If the optional remote dashboard is used, dashboard requests, transferred files and OAuth callback traffic pass through its configured tunnel provider. Administrators and people authorized to access the device or dashboard may also access available data. Provider logging and retention are governed by the provider’s configuration and policies.

When these public information pages are hosted by GitHub Pages, GitHub records visitors’ IP addresses for security purposes. These pages do not host USB backups or OAuth credentials. See GitHub Pages information and the GitHub privacy statement.

Optional dashboard information

When enabled, the dashboard stores local usernames, roles and password hashes, and uses session and security cookies. Completed web uploads are retained separately. Dashboard access does not itself establish that a file has been backed up to Google Drive.

Retention and deletion

Version 1 has no fixed automatic deletion period for originals, staged files, historical versions or backup history. Removing a file from CLOUDSTICK does not automatically delete its retained local copies or cloud versions. Storage can fill, and operator-managed retention is necessary.

Revoking Google access does not erase local files, stored credential copies, metadata or existing Drive backups. Deletion requires separate, deliberate handling of local storage, private credential backups and Google Drive contents. Google’s own retention and trash rules apply to data on its service. Comprehensive one-click deletion is not implemented.

Connectivity and authorization failures

Without an approved working connection, captured files remain locally stored and uploads pause. Retryable failures use delayed retries. Invalid authorization, local corruption or other non-retryable failures may require operator intervention. Queued or staged data must not be treated as cloud-verified.

Revoking access

Visit Google Account connections, select this application and remove its access to your Google Account. Future Google operations will require valid authorization. Removing access does not delete data already stored by the application. See Google’s instructions.

Contact

General support and non-sensitive privacy questions can be submitted through the project’s issue tracker. For private questions, email rtariq2014@gmail.com. Do not publish credentials or personal backup contents in an issue.
